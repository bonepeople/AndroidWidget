## Release Note

AndroidWidget 1.7.2 improves failure isolation in the shared `CoroutinesHolder` scopes, marks `AppData` read results for static-analysis checks, and adds comprehensive multilingual feature documentation. Existing integrations can upgrade without source or configuration changes, but applications that rely on one failed shared-scope coroutine canceling sibling work should review the new supervision behavior.

### Changed: Isolated Failures in `CoroutinesHolder` Scopes

`CoroutinesHolder.default`, `CoroutinesHolder.main`, and `CoroutinesHolder.io` now use a `SupervisorJob` instead of a regular `Job`. When a child coroutine fails, the other children in the same shared scope are no longer canceled automatically. This makes independent background, main-thread, and I/O tasks more resilient to an unrelated task failure.

This change does not suppress coroutine exceptions or make the global scopes lifecycle-aware. Exceptions still follow the normal coroutine exception-handling rules, and UI work tied to an `Activity` or `Fragment` should continue to use an appropriate lifecycle-aware scope. Applications that intentionally used failure propagation between tasks should place those related tasks in a separately owned structured-concurrency scope.

See the [CoroutinesHolder documentation](../features/CoroutinesHolder/README.md) for usage guidance.

### Changed: `AppData` Read Results Are Checked

All `AppData` value-reading APIs now carry AndroidX's `@CheckResult` annotation. This covers the suspending getters, synchronous getters, and `Flow` getters for `String`, `Int`, `Long`, `Float`, `Double`, and `Boolean` values.

Android Lint can now report a result that is read and then discarded, helping detect ineffective storage access or a `Flow` that is created but never collected. The annotation does not change method signatures, returned values, default-value behavior, persisted data, or runtime execution. Projects that treat lint warnings as errors may need to correct existing call sites that ignore these results.

See the [AppData documentation](../features/AppData/README.md) for supported access patterns.

### New: Multilingual Feature Documentation

The project documentation now includes a categorized feature index and individual usage guides in English, Simplified Chinese, and Spanish for the library's holders, utilities, activity-result helpers, animation support, resource helpers, and RecyclerView decorations. Public component KDoc also links to the feature documentation to make API guidance easier to discover from source and IDE documentation.

### Compatibility

This release does not change the minimum, target, or compile SDK; Kotlin, Java, Android Gradle Plugin, or Gradle requirements; AndroidX or third-party dependency versions; library Manifest entries; consumer permissions or initialization requirements; persisted data formats; or ProGuard/R8 rules. Public method signatures remain compatible with 1.7.1.

### Upgrade Recommendation

Upgrade to 1.7.2 for safer isolation between independent coroutines launched in the shared `CoroutinesHolder` scopes and better static detection of ignored `AppData` results. Review only code that intentionally depends on sibling cancellation after a coroutine failure or currently ignores an `AppData` getter result.

## Upgrade Guide

This guide assumes the project is upgrading from 1.7.1 to 1.7.2. If the project is on an earlier version, apply the Upgrade Guides for each intervening release first.

### Required Actions

- [Required] Update the AndroidWidget dependency from `1.7.1` to `1.7.2`. For a direct JitPack declaration, search for `com.github.bonepeople:AndroidWidget:1.7.1` and replace it with:

```groovy
implementation 'com.github.bonepeople:AndroidWidget:1.7.2'
```

  If the version is managed by a version catalog, build property, or shared dependency constant, update that single source instead of each generated or resolved declaration.

No source, Manifest, permission, initialization, dependency-alignment, data-migration, or ProGuard/R8 changes are required for existing integrations.

### Recommended Checks

- [Recommended if shared-scope tasks depend on fail-fast cancellation] Search for `CoroutinesHolder.default.launch`, `CoroutinesHolder.main.launch`, and `CoroutinesHolder.io.launch`. Review tasks that expect one child's failure to cancel other children launched in the same shared scope. Those sibling tasks now continue running; keep mutually dependent work in a separately owned structured-concurrency scope when failure propagation is required.
- [Recommended if lint warnings fail the build] Search `AppData` call sites for `.getString`, `.getInt`, `.getLong`, `.getFloat`, `.getDouble`, and `.getBoolean` to include the suspending, `Sync`, and `Flow` variants. For every ignored getter result, either use or collect the result as appropriate, or remove the ineffective read. The new `@CheckResult` annotations do not require changes where the returned value or `Flow` is already consumed.

### Verification

- [Recommended] Verify that an expected long-running task launched in a shared `CoroutinesHolder` scope continues when an unrelated sibling coroutine fails.
- [Recommended if related tasks must fail together] Verify those tasks still use an explicitly owned scope or structured parent whose cancellation semantics match the application's requirements.
- [Recommended] Run the consumer project's normal lint checks and confirm that no intentionally ignored `AppData` result remains.

## Changelog

- Replaced the root `Job` with `SupervisorJob` in `CoroutinesHolder.default`, `CoroutinesHolder.main`, and `CoroutinesHolder.io`, preventing a child failure from automatically canceling sibling coroutines in the same shared scope.
- Added AndroidX `@CheckResult` to the 18 suspending, synchronous, and `Flow`-based `AppData` getters for the supported value types.
- Added a categorized feature documentation index and individual English, Simplified Chinese, and Spanish usage guides across the documented library components.
- Added links from public component KDoc to the corresponding feature documentation for easier discovery from source and IDE documentation.
