## Release Note

AndroidWidget 1.7.4 adds a read-only Window Insets stream to `InsetsLayout` and makes `AppKeyboard.showKeyboard()` request the software keyboard sooner. The release is backward-compatible for existing integrations and does not require source or configuration migration.

### New: Observe Window Insets from `InsetsLayout`

`InsetsLayout.insetsFlow()` now exposes the latest `WindowInsetsCompat` value as a read-only `StateFlow`:

```kotlin
fun insetsFlow(): StateFlow<WindowInsetsCompat>
```

This API lets a screen observe system bar, display cutout, and IME state without replacing the internal Window Insets listener used by `InsetsLayout`. The returned flow replays its latest value to new collectors. Before the first platform Insets dispatch, its value is an empty `WindowInsetsCompat`. The flow does not distinguish that initial placeholder from a platform result in which the queried Insets are genuinely zero.

The flow contains the complete Insets object received by the layout. The existing `typeMask` and `insetsMask` properties continue to control only the padding applied by `InsetsLayout`; they do not filter the value emitted by `insetsFlow()`.

Collect the flow from a lifecycle-aware coroutine when observation should stop while the screen is inactive. The returned `StateFlow` cannot be used to modify the layout's internal Insets state.

### Changed: Faster Software Keyboard Request

`AppKeyboard.showKeyboard(editText)` now waits 100 ms instead of 200 ms before requesting focus and showing the software keyboard. Its signature and calling pattern are unchanged. Input screens should feel more responsive, but applications or UI tests that depend on the previous timing should verify focus, navigation, and animation behavior after upgrading.

### Compatibility

This release does not change the minimum, target, or compile SDK; Kotlin, Java, Android Gradle Plugin, or Gradle requirements; AndroidX or third-party dependency versions; library Manifest entries; consumer permission or initialization requirements; data formats; or ProGuard/R8 rules.

The sample application's package reorganization and the feature index formatting changes do not affect library consumers.

### Upgrade Recommendation

Upgrade to 1.7.4 when a screen needs to observe the Insets received by an `InsetsLayout`, or to adopt the shorter keyboard-show delay. Existing integrations can update the dependency without code changes.

## Upgrade Guide

This guide assumes the project is upgrading from 1.7.3 to 1.7.4. If the project is on an earlier version, apply the Upgrade Guides for each intervening release first.

### Required Actions

- [Required] Update the AndroidWidget dependency from `1.7.3` to `1.7.4`. For a direct JitPack declaration, search for `com.github.bonepeople:AndroidWidget:1.7.3` and replace it with:

```groovy
implementation 'com.github.bonepeople:AndroidWidget:1.7.4'
```

  If the version is managed by a version catalog, build property, or shared dependency constant, update that single source instead of each generated or resolved declaration.

No source, Manifest, permission, initialization, dependency-alignment, data-migration, or ProGuard/R8 changes are required for existing integrations.

### Recommended Checks

- [Recommended if the project uses `AppKeyboard.showKeyboard`] Search for `AppKeyboard.showKeyboard(` and verify screens whose focus, entrance animation, navigation, or UI tests are timing-sensitive. The request is now posted after 100 ms instead of 200 ms; the public API and keyboard-show sequence are otherwise unchanged.
- [Recommended if the project installs a Window Insets listener on an `InsetsLayout`] Search for `ViewCompat.setOnApplyWindowInsetsListener(` and review results whose target view is `com.bonepeople.android.widget.view.InsetsLayout`. Installing another listener directly on the same view can replace the listener that maintains the layout's padding. When the additional listener only observes Insets, use `insetsFlow()` instead.

### Optional Adoption: Observe Insets Without Replacing the Layout Listener

- [Optional] Use `InsetsLayout.insetsFlow()` when code needs the latest Insets received by the layout for behavior beyond its built-in padding adjustment. Collect it with the screen's lifecycle and query the required Insets type from each value:

```kotlin
viewLifecycleOwner.lifecycleScope.launch {
    viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
        binding.insetsLayout.insetsFlow().collect { insets ->
            val imeVisible = insets.isVisible(WindowInsetsCompat.Type.ime())
            updateForKeyboard(imeVisible)
        }
    }
}
```

The flow immediately emits its current value to a new collector. Before the system has dispatched Window Insets, that value is empty, and the flow does not identify whether an empty value is the initial placeholder or a measured zero-Inset result. Do not use `insetsFlow()` alone when that distinction matters. Keep an existing listener when it consumes or transforms Insets, targets another view, or performs behavior that cannot be represented by observing the latest state.

### Verification

- [Recommended] Verify any adopted `insetsFlow()` collection receives updates when system bars or the IME change and stops collecting according to the selected lifecycle state.
- [Recommended] Verify `InsetsLayout` still applies the expected padding for its configured `typeMask` and `insetsMask`; observing the flow should not require changing either property.
- [Recommended] Verify screens that call `AppKeyboard.showKeyboard()` focus the intended field and do not show the keyboard after the screen has already navigated away.

## Changelog

- Added `InsetsLayout.insetsFlow()` to expose the latest `WindowInsetsCompat` as a read-only `StateFlow` without exposing the layout's mutable internal state.
- Preserved the complete platform Insets value in `insetsFlow()` independently of the `typeMask` and `insetsMask` values used for automatic padding.
- Reduced the internal delay in `AppKeyboard.showKeyboard()` from 200 ms to 100 ms before requesting focus and showing the software keyboard.
- Reorganized the sample application's activities, service classes, and logging utility into feature-oriented packages, with corresponding Manifest and layout reference updates.
- Standardized heading levels and removed redundant separators from the English, Chinese, and Spanish feature indexes.
