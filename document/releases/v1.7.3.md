## Release Note

AndroidWidget 1.7.3 introduces `InsetsLayout` for automatic system bar and software keyboard padding, adds key-existence checks to `AppData`, splits long `AppLog` messages into multiple log entries, and exposes the library build time for diagnostics. Most existing integrations can upgrade without changes. Kotlin call sites that pass the `AppData.remove` argument by its old name require a small source migration.

### New: Automatic Window Insets Padding with `InsetsLayout`

`com.bonepeople.android.widget.view.InsetsLayout` is a `ConstraintLayout` that can add selected Window Insets to its existing padding. In XML, use the `app:insets` flags to select the affected edges:

```xml
<com.bonepeople.android.widget.view.InsetsLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:paddingStart="16dp"
    android:paddingEnd="16dp"
    app:insets="top|bottom">

    <!-- child views -->
</com.bonepeople.android.widget.view.InsetsLayout>
```

The available edge flags are `none`, `top`, `bottom`, `left`, `right`, and `all`. The corresponding programmatic constants are `INSET_NONE`, `INSET_TOP`, `INSET_BOTTOM`, `INSET_LEFT`, `INSET_RIGHT`, and `INSET_ALL`. The edge mask defaults to `none`, so the layout does not add Insets until at least one edge is selected.

By default, `typeMask` reads the combined `WindowInsetsCompat.Type.systemBars()` and `WindowInsetsCompat.Type.ime()` Insets. Set `typeMask` when a screen needs a different source, and set `insetsMask` to select edges programmatically. The calculated Insets are added to the layout's base padding, and later `setPadding()` calls replace that base padding before Insets are reapplied.

`InsetsLayout` installs its own Window Insets listener. Installing another listener directly on the same view replaces the listener that drives automatic padding. Keep a custom listener-based implementation when the screen must consume or transform Insets, coordinate an Insets animation, or perform behavior beyond additive padding on selected edges.

### New: Check Whether `AppData` Contains a Key

`AppData.contains(name)` is a suspending API that reports whether the selected `AppData` store contains a value with the supplied key name:

```kotlin
if (AppData.default.contains("access_token")) {
    restoreSession()
}
```

The check is based on the key name and works regardless of the stored value type. It is useful when a missing value must be distinguished from a value equal to a getter's default.

### Breaking Change: Renamed `AppData.remove` Parameter

The `String` parameter of `AppData.remove` is named `name` instead of `key`. The JVM method signature is unchanged, so Java calls, Kotlin positional calls, and already compiled callers are unaffected. Kotlin source that uses the named argument `remove(key = ...)` must change it to `remove(name = ...)` or use a positional argument before recompiling against 1.7.3.

### Changed: Long `AppLog` Messages Are Split

`AppLog.verbose`, `debug`, `info`, `warn`, and `error` now split each assembled message into entries of at most 3,000 characters. This reduces the risk of losing the tail of a long message to platform log-length limits. The tag and log level are preserved for every chunk, while an optional `Throwable` is attached only to the final chunk.

Method signatures and the global and per-instance logging switches are unchanged. Log processors and tests that assume one output entry per `AppLog` call should account for multiple entries when a message exceeds the chunk limit.

When the assembled message is empty, `AppLog` now emits no platform log entry. This occurs for an empty string when both thread and stack metadata are disabled.

### New: Library Build Timestamp

`com.bonepeople.android.widget.BuildConfig.buildTime` exposes the library artifact build time as Unix epoch milliseconds. The library build also prints the same timestamp in UTC and epoch-millisecond form to the Gradle lifecycle log. Applications can include the generated field in diagnostics when they need to identify the exact library build.

### Compatibility

Except for the Kotlin named-argument migration for `AppData.remove`, this release does not require consumer source changes. It does not change the minimum, target, or compile SDK; Kotlin, Java, Android Gradle Plugin, or Gradle requirements; AndroidX or third-party dependency versions; library Manifest entries; consumer permissions or initialization requirements; persisted data formats; or ProGuard/R8 rules.

### Upgrade Recommendation

Upgrade to 1.7.3 to replace repeated additive Window Insets padding code with `InsetsLayout`, distinguish missing `AppData` keys from stored default values, or split long log output automatically. Existing integrations can update the dependency after migrating any Kotlin `AppData.remove(key = ...)` named-argument calls.

## Upgrade Guide

This guide assumes the project is upgrading from 1.7.2 to 1.7.3. If the project is on an earlier version, apply the Upgrade Guides for each intervening release first.

### Required Actions

- [Required] Update the AndroidWidget dependency from `1.7.2` to `1.7.3`. For a direct JitPack declaration, search for `com.github.bonepeople:AndroidWidget:1.7.2` and replace it with:

```groovy
implementation 'com.github.bonepeople:AndroidWidget:1.7.3'
```

  If the version is managed by a version catalog, build property, or shared dependency constant, update that single source instead of each generated or resolved declaration.
- [Required if Kotlin code calls `AppData.remove` with a named argument] Search for `remove(key =` and review results that call `com.bonepeople.android.widget.util.AppData.remove`. Rename only those arguments to `name`, or switch them to positional calls:

```kotlin
// Before
data.remove(key = "access_token")

// After
data.remove(name = "access_token")
```

  Java calls and Kotlin calls such as `data.remove("access_token")` require no change. The old named argument does not compile against 1.7.3, although the JVM method signature remains unchanged.

No other source, Manifest, permission, initialization, dependency-alignment, data-migration, or ProGuard/R8 changes are required for existing integrations.

### Recommended Checks

- [Recommended if log output is parsed or asserted] Search for calls to `AppLog.verbose(`, `AppLog.debug(`, `AppLog.info(`, `AppLog.warn(`, and `AppLog.error(` whose messages can exceed 3,000 characters. Update log parsers, uploaders, or tests that assume one platform log entry per call so they can accept ordered chunks. When a `Throwable` is supplied, only the final chunk contains it.
- [Recommended if empty log messages are intentional] Review `AppLog` calls that can receive an empty string while both `showThreadInfo` and `showStackInfo` are disabled. These calls no longer emit a platform log entry; use a non-empty message when an entry is required.

### Optional Adoption: Replace Additive Window Insets Padding Boilerplate

- [Optional] Search for `ViewCompat.setOnApplyWindowInsetsListener(` and review listeners whose only purpose is to add system bar or IME Insets to selected padding edges. Replace those listeners with `com.bonepeople.android.widget.view.InsetsLayout` when the additive-padding behavior is equivalent:

```xml
<com.bonepeople.android.widget.view.InsetsLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:id="@+id/insetsLayout"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    app:insets="top|bottom" />
```

The default source mask combines system bars and the IME. When only system bars should affect padding, configure the source mask in code:

```kotlin
binding.insetsLayout.typeMask = WindowInsetsCompat.Type.systemBars()
```

Do not perform an unreviewed global replacement. Keep the existing listener when it consumes or transforms Insets, targets a view that cannot become a `ConstraintLayout`, drives translation or animation, or applies behavior other than padding. Do not install another Window Insets listener on the adopted `InsetsLayout`, because it would replace the layout's internal listener.

### Optional Adoption: Distinguish Missing `AppData` Keys

- [Optional] Search `AppData` reads for sentinel defaults used only to determine whether a value has ever been stored. Replace that existence test with the suspending `contains(name)` API while retaining the typed getter for the value:

```kotlin
val data = AppData.default
if (data.contains("launch_count")) {
    val launchCount = data.getInt("launch_count")
    restoreLaunchCount(launchCount)
}
```

`contains` checks the selected store by key name regardless of value type. Call it from a coroutine or another suspending function. Keep a direct getter with a default when missing and stored-default values intentionally have the same meaning.

### Optional Adoption: Include the Library Build Time in Diagnostics

- [Optional] Use `com.bonepeople.android.widget.BuildConfig.buildTime` when diagnostic output needs the library artifact's build time in Unix epoch milliseconds. Do not treat this value as the application build time or installation time.

### Verification

- [Recommended] Verify each adopted `InsetsLayout` adds Insets only to the selected edges, preserves its intended base padding, and updates correctly when the software keyboard appears or disappears.
- [Recommended] Verify any adopted `AppData.contains` call distinguishes a missing key from stored values equal to the getter default, including values stored under non-string types.
- [Recommended if `AppData.remove` named arguments were migrated] Verify the affected Kotlin source now compiles with `name =` or a positional argument and still removes the intended key.
- [Recommended] Verify long `AppLog` messages remain in order and downstream log handling accepts multiple entries; when a `Throwable` is logged, verify it appears with the final chunk.

## Changelog

- Added `com.bonepeople.android.widget.view.InsetsLayout`, a `ConstraintLayout` that listens for `WindowInsetsCompat` changes and adds selected Insets to its base padding.
- Added the `app:insets` XML flag attribute with `none`, `top`, `bottom`, `left`, `right`, and `all` edge options, together with matching `InsetsLayout` constants and the programmatic `insetsMask` property.
- Added `InsetsLayout.typeMask`, defaulting to system bar and IME Insets, for programmatic selection of the Window Insets sources used for padding.
- Added the suspending `AppData.contains(name)` API to check key existence by name independently of the stored value type.
- Renamed the `AppData.remove` parameter from `key` to `name`; the JVM signature and positional-call behavior remain unchanged, while Kotlin source using the old named argument must migrate.
- Split assembled `AppLog` messages into chunks of at most 3,000 characters across all five log levels, attaching an optional `Throwable` only to the final chunk and emitting no entry for an empty assembled message.
- Added `BuildConfig.buildTime` as an epoch-millisecond library build timestamp and added UTC and epoch-millisecond timestamp output to the library's Gradle lifecycle log.
