## Release Note

This release introduces a coroutine-based runtime permission API with explicit permission statuses, while keeping the existing callback API available for compatibility. It also formalizes the library's Apache License 2.0 distribution metadata. Existing integrations continue to work, but new code should use the coroutine API.

### New: Coroutine-Based `AppPermission`

A new permission utility is available under `com.bonepeople.android.widget.util.permission`:

- **`AppPermission.checkStatus(permission)`** synchronously returns the current `PermissionStatus` for one permission.
- **`AppPermission.request(vararg permissions)`** starts the Android permission flow and suspends until it completes.
- **`PermissionResult.permissionStatuses`** reports the status of every supplied permission in the original order.
- **`PermissionResult.allGranted()`** reports whether every supplied permission is granted.
- **`PermissionStatus.isGranted()`** and **`PermissionStatus.isRequestable()`** provide direct status checks.

Permissions that are already granted are not included in the system request, but remain present in the returned result. After a request, a denied permission is reported as `DENIED` when Android allows the regular request flow to continue, or `REQUEST_BLOCKED` when it does not. `REQUEST_BLOCKED` may require directing the user to system settings.

Call `request()` from a coroutine, preferably from a lifecycle-aware scope. If a request must display the system permission UI and no active `Activity` is available, the call throws `IllegalStateException`.

See [AppPermission documentation](../features/AppPermission/README.md) for complete usage and status-handling guidance.

### Deprecated: Callback-Based `AppPermission`

The callback API at `com.bonepeople.android.widget.util.AppPermission` is deprecated but remains functional in this release. Migrate to `com.bonepeople.android.widget.util.permission.AppPermission` to use synchronous status checks, structured results, and coroutine-based requests.

Replace the callback flow:

```kotlin
com.bonepeople.android.widget.util.AppPermission.request(permission)
    .onResult { allGranted, permissionResult ->
        if (allGranted) startFeature()
    }
```

with a lifecycle-aware coroutine:

```kotlin
lifecycleScope.launch {
    val result = com.bonepeople.android.widget.util.permission.AppPermission.request(permission)
    if (result.allGranted()) startFeature()
}
```

Migration is recommended for new development but is not required immediately because the deprecated API has not been removed.

### Permission Status Limitation

`PermissionStatus.NOT_REQUESTED` is defined for status modeling, but first-request detection is not implemented in this release. An ungranted permission therefore returns `DENIED` before a request. Code should not depend on receiving `NOT_REQUESTED` from `checkStatus()`.

### License and Compatibility

The project now includes the Apache License 2.0 text, and published Maven metadata declares the same license. This release does not change the minimum SDK, target SDK, compile SDK, Java compatibility, Kotlin version, Android Gradle Plugin requirement, or library dependency versions. The AndroidX splash screen dependency added to the sample application is not exposed to library consumers.

### Upgrade Recommendation

Upgrade to adopt structured permission statuses and request permissions from a lifecycle-aware coroutine scope. Existing integrations can upgrade without code changes, then migrate away from the deprecated callback API when convenient.

## Changelog

- Added `com.bonepeople.android.widget.util.permission.AppPermission` with synchronous `checkStatus` and suspending `request` APIs.
- Added `PermissionResult` to return every requested permission status and provide the `allGranted` aggregate check.
- Added `PermissionStatus` values for granted, not-yet-requested, denied, and request-blocked states, together with `isGranted` and `isRequestable` helpers.
- Classified denied request results as `DENIED` or `REQUEST_BLOCKED` by using Android's permission-rationale signal.
- Filtered already-granted permissions out of the system request while preserving them in the returned result.
- Deprecated the callback-based `com.bonepeople.android.widget.util.AppPermission` API without removing it.
- Updated English, Chinese, and Spanish `AppPermission` documentation with coroutine usage, migration examples, status semantics, and limitations.
- Migrated the sample permission flow from callback chaining to `lifecycleScope` and the coroutine-based API.
- Added an AndroidX splash screen launcher to the sample application, renamed its main screen to `HomeActivity`, and made back navigation remove the sample task.
- Added the Apache License 2.0 text and declared the license in Maven publication metadata.
- Configured Gradle console output to use UTF-8 and simplified the library build-start log prefix.
