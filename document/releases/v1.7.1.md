## Release Note

AndroidWidget 1.7.1 extends time formatting with locale selection and support for Android versions below 8.0, adds reusable file-size and running-service utilities, and lets `AppLog` include the calling thread name. Kotlin call sites that invoke `AppTime.formatTime` normally remain source-compatible, while Java callers, callable references whose type is inferred, and precompiled consumers must account for its changed signature.

### Breaking Change: Expanded `AppTime.formatTime` Signature

`AppTime.formatTime` now accepts a fourth parameter named `local` with a default value of `Locale.getDefault()`. Locale-sensitive pattern elements such as month and weekday names can therefore be formatted for a selected locale:

```kotlin
val text = AppTime.formatTime(
    timestamp = System.currentTimeMillis(),
    pattern = "dd MMMM yyyy",
    timeZone = TimeZone.getTimeZone("UTC"),
    local = Locale.US
)
```

The method no longer requires Android 8.0 (API 26). It uses `DateTimeFormatter` on API 26 and later and falls back to `SimpleDateFormat` on older supported Android versions, allowing the same API to be called down to the library's minimum SDK.

The added parameter changes the JVM method signature. Existing Kotlin source calls that pass up to the original three parameters continue to compile because `local` has a default value. Java calls must supply a `Locale`, and previously compiled code that directly references the old signature must be recompiled against 1.7.1. A Kotlin callable reference with an explicitly expected three-argument function type can use default-argument adaptation, but a reference whose type is inferred now has four parameters and may require a source change.

See the [AppTime documentation](../features/AppTime/README.md) for usage examples.

### New: Human-Readable Binary File Sizes

`AppText.formatFileSize(size)` converts a byte count into a compact value using base-1024 units such as `KiB`, `MiB`, and `GiB`. It uses at most one fractional digit, applies the default locale's decimal formatting, and returns `0 B` for zero or negative input:

```kotlin
val size = AppText.formatFileSize(1_048_576)
// "1 MiB"
```

The fixed IEC unit labels distinguish this API from formatters that use decimal units or fully localized unit text. See the [AppText documentation](../features/AppText/README.md) for related text utilities.

### New: In-App Service Status Check

`AppSystem.checkServiceRunning(serviceClass)` checks the running-service list for a service class name in the current application:

```kotlin
val running = AppSystem.checkServiceRunning(MyService::class.java)
```

The API relies on the deprecated platform `ActivityManager.getRunningServices` query. It is intended only as a best-effort check for services in the same application and may be inaccurate on Android 8.0 and later because of platform restrictions. It should not be used as an authoritative cross-application service monitor. See the [AppSystem documentation](../features/AppSystem/README.md) for other system helpers.

### New: Optional Thread Names in `AppLog`

Each `AppLog` instance now exposes `showThreadInfo`. When enabled, every log message from that instance is prefixed with the current thread name, such as `[main]`. The option is disabled by default, so existing log output is unchanged unless it is explicitly enabled. It can be combined with `showStackInfo` when both execution and call-site context are useful.

See the [AppLog documentation](../features/AppLog/README.md) for configuration examples.

### Compatibility

Except for the `AppTime.formatTime` JVM signature change, this release requires no consumer source or configuration migration. It does not change the minimum, target, or compile SDK; Kotlin, Java, Android Gradle Plugin, or Gradle requirements; library dependency versions; Manifest entries; consumer permissions or initialization requirements; persisted data formats; or ProGuard/R8 rules. The Fragment KTX dependency and service demonstration added to the sample application are not exposed to library consumers.

### Upgrade Recommendation

Upgrade to 1.7.1 when applications need locale-aware time output on all supported Android versions, consistent binary file-size labels, a best-effort in-app service check, or thread-aware logs. Recompile dependent modules, migrate Java calls to `AppTime.formatTime`, and review callable references whose type was inferred as part of the update.

## Upgrade Guide

This guide assumes the project is upgrading from 1.7.0 to 1.7.1. If the project is on an earlier version, apply the Upgrade Guides for each intervening release first.

### Required Actions

- [Required] Update the AndroidWidget dependency from `1.7.0` to `1.7.1`. For a direct JitPack declaration, search for `com.github.bonepeople:AndroidWidget:1.7.0` and replace it with:

```groovy
implementation 'com.github.bonepeople:AndroidWidget:1.7.1'
```

  If the version is managed by a version catalog, build property, or shared dependency constant, update that single source instead of each generated or resolved declaration.
- [Required if Java calls `AppTime.formatTime`] Search Java sources for `formatTime(` calls on `com.bonepeople.android.widget.util.AppTime`. Add the new fourth `Locale` argument:

```java
// Before
String text = AppTime.INSTANCE.formatTime(timestamp, pattern, timeZone);

// After
String text = AppTime.INSTANCE.formatTime(timestamp, pattern, timeZone, Locale.getDefault());
```

  Use a specific locale instead of `Locale.getDefault()` when output must be stable across device-language changes. Ordinary Kotlin calls may omit `local` because it has a default value.
- [Required if Kotlin code infers the type of an `AppTime.formatTime` reference] Search for `AppTime::formatTime`. References with an explicitly expected three-argument function type can use Kotlin's default-argument adaptation. If the type was inferred, preserve the previous three-argument shape with a lambda or update the surrounding code to accept a fourth `Locale` argument:

```kotlin
// Before: the inferred reference changes from three parameters to four
val formatter = AppTime::formatTime

// After
val formatter: (Long, String, TimeZone) -> String = { timestamp, pattern, timeZone ->
    AppTime.formatTime(timestamp, pattern, timeZone)
}
```

- [Required if a separately distributed module was compiled against 1.7.0] Recompile that module against AndroidWidget 1.7.1 before distributing or loading it with the updated library. The old three-parameter JVM method no longer exists, so unrecompiled bytecode that invokes it is not binary-compatible.

No Manifest, permission, initialization, dependency-alignment, data-migration, or ProGuard/R8 changes are required.

### Recommended Checks

- [Recommended if custom time patterns are used below API 26] Search for `AppTime.formatTime(` and verify locale-sensitive output and less-common pattern symbols on both pre-26 and API 26-or-later devices. The implementation uses `SimpleDateFormat` on older Android versions and `DateTimeFormatter` on newer versions, and the two formatter engines do not define every pattern symbol identically.
- [Recommended if adopting service-state checks] Verify `AppSystem.checkServiceRunning` on every supported Android version relevant to the application. Treat a `false` result as best-effort on Android 8.0 and later rather than proof that a service is stopped.

### Optional Adoption

- [Optional] Search for custom thread-name prefixes around `AppLog.verbose`, `debug`, `info`, `warn`, and `error` calls. When the prefix only reports `Thread.currentThread().name`, remove that duplication and enable `showThreadInfo` on the relevant `AppLog` instance. Keep custom formatting when logs require a different thread identifier or output layout.
- [Optional] Search for custom byte-count formatters or `Formatter.formatFileSize` calls. Replace them with `AppText.formatFileSize` only when base-1024 IEC labels, at most one fractional digit, and `0 B` for non-positive values match the desired behavior. Keep the existing formatter when fully localized units, decimal scaling, or different negative-value handling is required.
- [Optional] Search for direct `ActivityManager.getRunningServices` checks used only to inspect a service in the same application. Replace equivalent checks with `AppSystem.checkServiceRunning`, while preserving other state tracking for cross-application checks or flows that require authoritative service lifecycle information.

### Verification

- [Recommended] Verify `AppTime.formatTime` output with the application's selected locale, time zone, patterns, and minimum supported Android version.
- [Recommended] If `showThreadInfo` is enabled, verify the new `[thread-name]` prefix is accepted by log parsers and assertions.
- [Recommended] If `formatFileSize` is adopted, verify boundary values such as `0`, `1023`, `1024`, and `1048576` against the application's display requirements.

## Changelog

- Added the `local` parameter to `AppTime.formatTime`, applied it to locale-sensitive formatting, and added a `SimpleDateFormat` fallback so the API works below Android 8.0.
- Added `AppText.formatFileSize` to convert byte counts into default-locale numbers with base-1024 IEC unit labels and at most one fractional digit.
- Added `AppSystem.checkServiceRunning` for best-effort detection of a service class within the current application, with documented Android 8.0-or-later platform limitations.
- Added the per-instance `AppLog.showThreadInfo` option and unified message assembly so thread and stack information can be included together across all log levels.
