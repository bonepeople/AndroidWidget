## Release Note

AndroidWidget 1.7.0 completes the removal of APIs deprecated for this major-minor boundary, removes the MMKV-backed `AppStorage` implementation and its dependency, validates `AppData` store names before creating files, and makes verbose logs honor `AppLog.showStackInfo`. This is a breaking release for projects that still use the removed APIs or rely on legacy MMKV data.

### Breaking Change: Removed `AppStorage` and MMKV

`com.bonepeople.android.widget.util.AppStorage` has been removed after its earlier deprecation, and AndroidWidget no longer declares `com.tencent:mmkv:1.2.14`. New storage code should use the DataStore-backed `AppData` API.

Existing `AppStorage` data is not read, converted, or deleted automatically by 1.7.0. `AppStorage` and `AppData` use different storage locations and formats, so applications that must preserve legacy values need a staged migration while still using AndroidWidget 1.6.7. Applications that upgrade directly without their own MMKV migration path can no longer access those values through AndroidWidget.

`AppData` provides suspending, synchronous, and `Flow`-based access for supported value types, but it does not replace the removed `AppStorage.backup` and `AppStorage.restore` APIs. Projects that require backup and restore must provide a separate implementation appropriate to their data and lifecycle requirements.

See the [AppData documentation](../features/AppData/README.md) for the replacement storage API.

### Breaking Change: Removed Deprecated Convenience APIs

The following deprecated APIs have been removed:

- `ActivityHolder` member extensions `Activity.putExtra`, `Activity.getExtra`, and `Activity.removeExtra`. Use `ActivityHolder.putData`, `ActivityHolder.getData`, and `ActivityHolder.removeData` with an explicit `Activity` argument.
- `AppKeyboard.showKeyboard(Context, EditText)`. Use `AppKeyboard.showKeyboard(EditText)`; the removed `Context` argument was unused.
- `AppKeyboard.hideKeyboard(Context, View?)`. Use `AppKeyboard.hideKeyboard()`; the replacement resolves the focused view from the top activity, matching the behavior to which the deprecated overload delegated.
- Companion shortcuts `AppLog.verbose`, `debug`, `info`, `warn`, and `error`. Use the same methods on `AppLog.defaultLog`, `AppLog.tag(tag)`, or another `AppLog` instance.

These removals are source- and binary-incompatible. Projects that completed the deprecation migrations before upgrading require no further changes for these APIs.

### Changed: `AppData` Store Name Validation

`AppData.create(storeName)` now throws `IllegalArgumentException` before creating a store when the name is blank, longer than 255 characters, contains an ISO control character, contains any of `<`, `>`, `:`, `"`, `/`, `\`, `|`, `?`, or `*`, or ends with a period or space.

The default store name remains valid. Projects that derive names from user input, server data, file paths, or other dynamic values should validate or map those values to stable application-owned identifiers before calling `create`.

### Fixed: Stack Information in Verbose Logs

`AppLog.verbose` now uses the same message assembly as the other log levels. When `showStackInfo` is enabled on an `AppLog` instance, verbose messages now include the configured call-site information instead of ignoring the option. The default remains `false`, so existing verbose output is unchanged unless stack information was explicitly enabled.

### Build, Publication, and Dependency Updates

The AndroidWidget source build now uses Android Gradle Plugin 8.2.2, Gradle 8.5, Kotlin Gradle Plugin 1.8.22, and JDK 17 instead of Android Gradle Plugin 7.3.1, Gradle 7.4, Kotlin 1.7.20, and JDK 11. These versions apply when building the repository from source; consuming the published AAR does not by itself require matching Gradle or Android Gradle Plugin versions.

The library publication now includes a sources JAR for IDE navigation and debugging. MMKV is no longer a runtime dependency of AndroidWidget. Other library dependency versions and the minimum, target, and compile SDK levels are unchanged.

### Upgrade Recommendation

Upgrade after replacing all APIs deprecated for removal in 1.7.0 and completing any required MMKV-to-`AppData` migration. Projects that no longer use `AppStorage` or the removed convenience APIs can update directly, then review dynamic `AppData` store names and Kotlin toolchain compatibility.

## Upgrade Guide

This guide assumes the project is upgrading from 1.6.7 to 1.7.0. If the project is on an earlier version, apply the Upgrade Guides and deprecation migrations for each intervening release first.

### Required Actions

- [Required] After completing any applicable legacy-storage migration described in this guide, update the AndroidWidget dependency from `1.6.7` to `1.7.0`. For a direct JitPack declaration, search for `com.github.bonepeople:AndroidWidget:1.6.7` and replace it with:

```groovy
implementation 'com.github.bonepeople:AndroidWidget:1.7.0'
```

  If the version is managed by a version catalog, build property, or shared dependency constant, update that single source instead of each generated or resolved declaration.
- [Required if the project uses `AppStorage`] Search for `com.bonepeople.android.widget.util.AppStorage`, `import com.bonepeople.android.widget.util.AppStorage`, and `AppStorage.`. Before removing the legacy access path, migrate known keys to `AppData` in an application release that still uses AndroidWidget 1.6.7:

```kotlin
suspend fun migrateLegacyStorage() {
    val target = AppData.default
    if (!target.getBoolean("legacy_mmkv_migrated")) {
        target.putString("display_name", AppStorage.getString("display_name"))
        target.putBoolean("notifications", AppStorage.getBoolean("notifications"))
        target.putBoolean("legacy_mmkv_migrated", true)
    }
}
```

  Enumerate the application's actual key and type schema instead of copying the example keys. Release and run this migration before shipping a build that removes `AppStorage`; AndroidWidget 1.7.0 cannot read the old values for the application. Do not remove the legacy path until the application's migration rollout requirements are satisfied.

  Replace ordinary access with the equivalent `AppData` instance methods. Suspending code can use `putString`, `getString`, and the other typed methods; non-suspending code can use the corresponding `Sync` variants where blocking is acceptable. Replace `AppStorage.remove(key)` with the suspending `AppData.default.remove(key)`. There is no direct `AppData` replacement for `AppStorage.backup` or `AppStorage.restore`, so implement a separate backup format when those operations are required.
- [Required if the project uses removed `ActivityHolder` extensions] Search for `putExtra(`, `getExtra(`, and `removeExtra(` in scopes that import or expose the `ActivityHolder` member extensions. Replace only those calls as follows:

```kotlin
// Before
activity.putExtra("request", request)
val request = activity.getExtra("request")
activity.removeExtra("request")

// After
ActivityHolder.putData(activity, "request", request)
val request = ActivityHolder.getData(activity, "request")
ActivityHolder.removeData(activity, "request")
```

  Do not replace unrelated `Intent.putExtra` or other APIs with the same method names.
- [Required if the project uses removed `AppKeyboard` overloads] Search for `AppKeyboard.showKeyboard(` and remove the old `Context` argument from two-argument calls. Search for `AppKeyboard.hideKeyboard(` and replace calls that pass `Context` and `View?` with the parameterless method:

```kotlin
// Before
AppKeyboard.showKeyboard(context, editText)
AppKeyboard.hideKeyboard(context, focusedView)

// After
AppKeyboard.showKeyboard(editText)
AppKeyboard.hideKeyboard()
```

- [Required if the project uses `AppLog` companion shortcuts] Search for `AppLog.verbose(`, `AppLog.debug(`, `AppLog.info(`, `AppLog.warn(`, and `AppLog.error(`. Replace each companion call with an instance call:

```kotlin
// Before
AppLog.error("Unable to load", throwable)

// After: retain the previous default tag
AppLog.defaultLog.error("Unable to load", throwable)

// Or use an explicit component tag
AppLog.tag("Repository").error("Unable to load", throwable)
```

- [Required if the project builds AndroidWidget from source] Use JDK 17 with the repository's Gradle 8.5 wrapper and Android Gradle Plugin 8.2.2 configuration. JDK 11 is no longer sufficient for this source build.

No consumer Manifest, permission, initialization, SDK-level, persisted `AppData` format, or ProGuard/R8 changes are required.

### Recommended Checks

- [Recommended if store names are dynamic] Search for `AppData.create(` and review every result whose argument is not a fixed application constant. Ensure the final name is non-blank, no longer than 255 characters, contains no ISO control characters or `< > : " / \ | ? *`, and does not end with a period or space. Map external identifiers to safe stable names rather than applying an unreviewed global character replacement.
- [Recommended if the consumer uses an older Kotlin plugin] AndroidWidget 1.7.0 is built with Kotlin 1.8.22. If the consumer build reports incompatible Kotlin metadata, update its Kotlin Gradle Plugin to 1.8.22 or another version compatible with the project's toolchain.
- [Recommended if the project used MMKV independently] Search build scripts and version catalogs for `com.tencent:mmkv` and verify the application declares the dependency directly at the version it intends to own. AndroidWidget no longer supplies MMKV at runtime.
- [Recommended if log output is parsed or asserted] Review `AppLog` instances with `showStackInfo = true`. Verbose messages now include the same ` @ Class.method:line` suffix as the other levels, so parsers and tests should accept the additional text.

### Verification

- [Recommended] Verify every required legacy MMKV value is present in `AppData` after the staged migration and remains available after upgrading to 1.7.0.
- [Recommended] Verify migrated keyboard calls still target the intended `EditText` and that parameterless hiding resolves the expected top activity and focused view.
- [Recommended] Verify all dynamic `AppData` store names are accepted, and verify invalid names fail at the application's validation boundary rather than during an unrelated workflow.
- [Recommended] Verify verbose logging with both `showStackInfo = false` and `showStackInfo = true` when log text is consumed programmatically.

## Changelog

- Removed the deprecated MMKV-backed `AppStorage` API, including its typed access, removal, backup, and restore operations.
- Removed the `com.tencent:mmkv:1.2.14` dependency from the library runtime dependency graph.
- Removed the deprecated `ActivityHolder` member extensions `Activity.putExtra`, `Activity.getExtra`, and `Activity.removeExtra` in favor of explicit `putData`, `getData`, and `removeData` calls.
- Removed the deprecated `AppKeyboard.showKeyboard(Context, EditText)` and `hideKeyboard(Context, View?)` overloads in favor of `showKeyboard(EditText)` and `hideKeyboard()`.
- Removed the deprecated `AppLog` companion logging shortcuts in favor of calls on `defaultLog`, tagged instances, or directly constructed instances.
- Added `AppData.create` validation for blank or oversized names, control characters, filesystem-invalid characters, and names ending with a period or space.
- Applied `AppLog.showStackInfo` to verbose output so all log levels use the same optional call-site suffix.
- Upgraded the source-build toolchain from Android Gradle Plugin 7.3.1, Gradle 7.4, Kotlin 1.7.20, and JDK 11 to Android Gradle Plugin 8.2.2, Gradle 8.5, Kotlin 1.8.22, and JDK 17.
- Added a sources JAR to the release publication for source navigation and debugging.
